# Architecture Decision Records

ADRs registram decisões relevantes e o motivo por trás delas. Não são changelogs nem documentação operacional.

## Formato

Cada ADR deve conter:

- **Status**: Proposed, Accepted, Superseded ou Deprecated;
- **Context**: problema e restrições;
- **Decision**: decisão adotada;
- **Alternatives considered**: alternativas avaliadas;
- **Consequences**: impactos positivos e negativos.

Use nomes numerados, como `0001-monorepo.md`. Decisões posteriores devem referenciar a decisão substituída quando aplicável.

## Novas decisões

Copie a estrutura abaixo:

```markdown
# ADR NNNN — Título

## Status

Accepted

## Context

## Decision

## Alternatives considered

## Consequences
```
